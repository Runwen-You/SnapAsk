# SnapAsk M6 发布核对表

本表用于每一个发布候选版本。`[x]` 只表示已有当前仓库实现或本机自动化证据；`[ ]`
表示发布候选仍需执行或需要外部环境。不得用单元测试推断真实硬件/系统矩阵已通过。

## 当前已有实现和本机证据

- [x] 保存、剪贴板、贴图、本地预览和 AI 发送复用同一 revision 缓存中的规范
  `RenderedSnapshot`；集成测试核对对象、PNG 和 SHA-256。
- [x] 编辑器显示、预览、标注和问题编辑阶段，本地假服务仍为 0 个截图请求；点击发送或
  `Ctrl+Enter` 后才收到唯一规范 PNG。
- [x] API Key 使用 Windows Credential Manager；普通 JSON/导出仅保存 `credentialRef`，
  明文凭据配置被拒绝，日志脱敏有自动化覆盖。
- [x] GDI 捕获、PNG/SHA、Base64/JSON 和大型预览缩放使用 `QThreadPool`，并对过期结果做
  UUID/revision/generation 校验。
- [x] 4K PNG p50 85.499 ms、p95 94.706 ms、最差 102.362 ms，满足 300 ms 目标。
- [x] 4K 拖动后续帧 p95 2.481 ms、最差 3.075 ms；首次静态背景单样本 25.349 ms。
- [x] 100 次真实产品 UI/本地网络流通过；工作集 18.4 → 峰值 29.2 → 结束 29.0 MiB。

上述性能和压力测试的输入边界见 `docs/performance-results.md`，不得简称为完整 4K 端到端
或真实桌面 100 次测试。

- [ ] 真实单 4K 活跃会话工作集目标 ≤ 180 MB。
- [ ] 真实长回答流式刷新间隔保持约 33～60 ms。
- [x] 最终 x64 stage 为 63.289 MiB，ZIP 为 26.532 MiB；stage 包含 app-local VC 运行库，
  因而也满足“不含 VC 运行库建议 ≤ 70 MB”的更宽松口径。

## 发布结论

在“每个候选包必须重新执行”、P0 smoke、隐私抓包和外部 Windows 矩阵仍有未勾选项目时，
结论只能是“本机实现与自动化已具备，平台发布验收未完成”，不能标记 M6 最终签字通过。
